# Teaching philosophy

Instruction should move from concrete observation to abstract understanding, then back to independent application. Start with accessible activities and progressively remove scaffolding.

## Teaching practices

- Use an initial readiness check rather than assuming prior knowledge.
- Introduce vocabulary through real examples and diagrams.
- Model how experts diagnose uncertainty and failure.
- Provide short feedback cycles and purposeful practice.
- Use pair discussion and demonstrations where useful.
- Allow multiple project forms to demonstrate the same competency.

## Sample assessment rubric

| Dimension | Emerging | Developing | Demonstrated |
| --- | --- | --- | --- |
| Conceptual understanding | Names a tool | Explains components with prompts | Explains system and trade-offs |
| Execution | Follows steps with assistance | Completes with occasional help | Repeats independently and safely |
| Debugging | Stops at an error | Tests likely causes | Uses evidence to isolate causes |
| Documentation | Incomplete notes | Records major steps | Reproducible explanation and reflections |
| Safety and ethics | Needs reminders | Applies key rules with prompts | Anticipates and explains risks |

Rubrics must be adapted for age, accessibility and specific module objectives.

## Example project evidence

A repository or project file, a small demo, setup notes, a test log, explanation of decisions, and reflection about limitations. Public publication must be optional and permission-based.

## Quality loop

Collect anonymous or consented feedback, review learner misconceptions, observe mentor time, revise modules, and periodically check whether skills transfer to unfamiliar tasks.
